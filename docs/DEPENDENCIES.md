# Dependencies

Cargo manifests list the exact direct requirements. The committed lockfile records the resolved versions and registry checksums. The package minimum is Rust 1.92; CI and local builds use the pinned Rust 1.95.0 toolchain because of Hayro 0.9.0. The CI checkout action is pinned to its upstream v4.2.2 commit.

A preliminary RustSec review used advisory database revision `c9f6c91a44dbad9d71742329e9df061279f9c4be`. The pinned Localwright revision uses Iced’s Tiny Skia software renderer and removes the affected `lru 0.12.5` dependency path (RUSTSEC-2026-0002 and RUSTSEC-2026-0253). Full license review, SBOM and native dependency review remain open.

The weekly/manual `security.yml` workflow runs pinned `cargo-audit` 0.23.0 against the committed lockfile and generates an all-features CycloneDX 1.5 SBOM with `cargo-cyclonedx` 0.5.10. It also creates a transitive Cargo license metadata inventory and fails if a dependency declares neither a license expression nor a license file. This inventory supports review; it does not determine which side of an upstream license alternative applies, approve redistribution, inspect linked native libraries, or replace human legal review. The audit and inventory are separate jobs so advisory findings do not suppress the inventory artifact.

The document stack uses lopdf 0.42.0 with optional features disabled and ZIP 9.0.5. The bounded page preview uses upstream Hayro 0.9.0 (`hayro`, Apache-2.0 OR MIT, copyright Laurenz Stampfl), a pure-Rust CPU PDF rasterizer built on `hayro-syntax`/`hayro-interpret` 0.9 and `vello_cpu` 0.3. It embeds standard fonts and CMaps by default. Hayro declares Rust 1.92; Document Studio's manifest MSRV is therefore 1.92 and its tested toolchain pin is 1.95.0. This choice avoids a required private native PDFium binary, but it is not a PDFium fidelity claim: upstream documents missing blend/isolation/knockout behavior and other PDF features. Preview output is a raster image and may omit or alter unsupported content. PDF parsing/rendering remains in-process and is not sandboxed; hostile decompression and CPU/memory exhaustion remain open risks.

The `pdf-preview` route reads a single regular input of at most 32 MiB, applies the existing 100,000-object and 1,000-page parser bounds, renders one requested page at a time, limits the result to 1,400 pixels per edge and 1.5 million pixels, and writes a new PNG without overwriting. Panics from the PDF parser/rasterizer are caught and returned as errors. These input/output bounds do not provide a hard process memory or execution-time limit. The native viewer renders pages on a background worker and allows only one render at a time; cancellation is observed between parser/render stages and cannot interrupt a rasterization already in progress.
