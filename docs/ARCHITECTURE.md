# Architecture

Document Studio: Local document interchange.

Localwright core contains serde-based domain contracts, request/response, capability and engine descriptors, job cancellation, bounded reads, no-clobber output and settings. It has no Iced dependency. Localwright UI is an optional dependency of the studios and provides a generic native operation workbench. It dispatches a single job to a background thread and receives the structured outcome through a channel. The same handler runs through the CLI. Studio processing lives in its own crate. No local server, system engine lookup or runtime network client is intentionally implemented.

Document Studio routes private OCR process execution through Localwright's hash-verified, bounded engine runtime on normal supported paths. The runtime hides the child console on Windows. The Linux private shared-library loader path and non-UTF-8 argument fallback still use a narrow direct runner because the shared API does not yet handle those platform-specific inputs. This is process hygiene, not an OS sandbox.

Source contracts version 0.1.0-alpha.1; pre-1.0 API is unstable. Use exact shared revision after import. New breaking changes require migration notes and all four consumer checks. Localwright core/UI supports Rust 1.88; Document Studio now requires Rust 1.92 for Hayro 0.9.0 and pins toolchain 1.95.0. No promise of ABI stability. Current settings schema 1. Request and outcome are internal alpha interchange, not stable project file formats.

The experimental `pdf-preview` route uses Hayro 0.9.0 (pure Rust, Apache-2.0 OR MIT) to rasterize one selected page, save a bounded PNG, and open a native PDF workspace. Its pixel budget is 1.5 million and maximum edge is 1,400 px. The workspace requests up to nine nearby thumbnails per navigation, caches at most twelve, and offers direct page selection, fit/zoom controls, native PDF opening, up to eight session-local recent documents, extraction of the selected page through the existing no-overwrite page-range handler, and clockwise/counterclockwise rotation of the selected page into a new copy. Zoom scales the existing bounded raster. Text-layer search uses lopdf 0.42 in a background task, caps accumulated extracted text at 8 MiB and visible results at 100 pages, and checks cooperative cancellation between pages. It does not OCR scanned pages; the size check occurs after per-page text extraction, so lopdf decompression remains without a hard memory cap. The renderer is not full PDFium fidelity and does not support all blending/transparency features. The viewer is a separate native window because the shared Localwright workbench currently presents text outcomes only.

Limitations: Basic DOCX only; inline Markdown and layout omitted. PDF parsing and decompression limits are incomplete, active content can survive split/merge, and these operations are not redaction or sanitization. Page-only merge drops page annotations, document-level metadata/bookmarks/forms, and may lose inherited or unusual structures; no independent reader validation yet. The new renderer and GUI viewer still require hosted multi-platform verification; process isolation and a complete hostile-input resource bound are absent. No Office fidelity, legacy converters or structural and visual comparison.
