# Offline manual | Document Studio

Development source only. Launch the GUI after compiling. Choose an operation, enter local input path and a new output path where needed, set the parameter as described under the operation selector, then Run. Status and errors are shown below. Cancel requests cooperative cancellation. The draft editor accepts transcript or plain text. Choose a theme to change workbench colors and control borders. UI scale adjusts the controls from 80% to 300% and remembers your appearance choices when you reopen the app. Most workbench operations still use typed paths; the native PDF viewer provides operating-system open and save dialogs. Full application-wide file dialogs and accessibility remain pending.

- `text-docx`: Writes literal paragraphs from UTF-8 text. Leading Markdown characters are preserved.
- `markdown-docx`: Basic ATX headings and literal paragraphs to DOCX.
- `ocr-png-pdf`: Create a new one-page PDF with the source PNG and recognized English text. The optional OCR build and matching installed pack are required.
- `ocr-pdf`: Create a searchable copy of a local PDF with 1–20 pages using the optional private English OCR build and matching installed pack. Every page is rasterized before OCR; vector content, annotations, forms, bookmarks and document metadata are not retained. The source is unchanged, output is created without overwriting, and this route is not sanitation or redaction. Review OCR against the original.
- `ocr-png`: English PNG OCR in an [optional engine build](OCR_ENGINE.md).
- `docx-text`: Preview UTF-8 main-body text or write it to a new `.txt` file. Paragraphs, tabs and line breaks are retained. Layout, list markers, headers, footnotes and images are omitted. Hidden body text may appear. Macros, linked resources and external XML entities are never loaded by this route.
- `epub-inspect`: Inspect the container, package metadata and reading-order spine of a bounded EPUB. An optional new `.json` report is supported. This checks only the structure needed by this route and is not a complete EPUB conformance validator.
- `epub-text`: Extract UTF-8 XHTML body text in spine reading order, optionally to a new `.txt` file. CSS/layout, images, navigation, annotations and scripts are not rendered or executed; DRM-protected content is not decrypted.
- `epub-markdown`: Export bounded EPUB package title, creators, language, spine chapter headings and XHTML body text as a new `.md` file. Markdown punctuation is escaped. This is structural text export, not layout-preserving conversion: inline styles, navigation, tables as layout, images, scripts and DRM-protected content are omitted.
- `markdown-epub`: Convert bounded UTF-8 Markdown to a new EPUB 3 book. The converter preserves CommonMark headings, emphasis, lists, tables, and code blocks. Pass optional metadata as JSON in the parameter field, for example `{"title":"Field Notes","language":"en"}`. External links and image resources are omitted (visible link/alt text remains); raw HTML is escaped as text. This is structural conversion, not page-layout or DOCX/ODT fidelity conversion. Input is limited to 4 MiB and generated output to 32 MiB.
- `epub-reader`: Open a bounded local EPUB in a separate native, offline reader. Use the chapter strip or previous/next chapter controls to follow the OPF spine, and previous/next text-page controls to read long chapters in 16 KiB UTF-8-safe sections. `A−` and `A+` adjust the text size from 12 to 30 pt. The reader offers an OS file picker and up to eight recent books for the current session. It displays extracted XHTML body text and basic title/creator/language metadata; it is not a layout renderer. CSS, images, tables as layout, page breaks, navigation structures, annotations, scripts, and DRM-protected content are not rendered, executed, or decrypted. Extraction is capped at 8 MiB for a book. Files are opened read-only and are never rewritten.
- `compare-text`: Provide the original UTF-8 file as input and the revised file path as the parameter. Preview changes or save a new `.txt` report. Escaped line endings make missing final newlines and CRLF changes visible. Each input is limited to 1 MiB and 50,000 lines. Highly dissimilar inputs can reach the diff work limit.
- `citation-validate`: Validate UTF-8 CSL JSON containing one reference object or an array of up to 10,000 references. Each entry needs a non-empty `type`; optional IDs and titles are checked. An optional `.json` output reports the validation result.
- `citation-convert`: Convert using the parameter `source->target`: `csl-json->ris`, `ris->csl-json`, `csl-json->bibtex`, or `ris->bibtex`. Choose a new `.json`, `.ris`, or `.bib` output matching the target. Inputs and outputs are limited to 8 MiB. The RIS reader accepts complete tagged records and rejects continuation lines. Unsupported fields are dropped. Review exported records; this route does not render or validate APA, Harvard, Vancouver, or IEEE styles.
- `pdf-info` reports the PDF version, page count, file size, and available title, author, subject, creator, and producer metadata with optional JSON output. Missing PDF metadata is returned as `null`. The native PDF workspace also shows the selected page's rendered dimensions in PDF points. Metadata comes from the document Info dictionary; it is descriptive and is not a sanitization check.
- `pdf-preview`: In the native workbench, enter an optional 1-based page number (default 1) and choose a new `.png` output. Run saves the bounded raster preview and opens the Document Studio PDF workspace. The workspace provides native PDF opening, up to eight recent documents for the current session, previous/next navigation, direct page selection, and a visible page strip with no more than nine thumbnails; the cache holds at most twelve. The selected page is highlighted and labeled with its current position. Fit, Actual, Zoom in, and Zoom out controls are available. `Extract page…`, the `Save range as PDF…` control, and the two `Rotate page…` controls save a new PDF copy based on the selected source or inclusive page range. Enter a range such as `2-4`; ranges are validated against the open document. `Move page earlier` and `Move page later` rearrange the selected page in the visible order; `Save reordered copy…` writes the complete order to a new `.pdf` using `pdf-reorder`, then opens that copy. The order state is bounded by the existing 1,000-page document limit. `Find in PDF` performs case-insensitive literal search over the PDF text layer, reports matching source pages, and navigates to a selected result. Search is limited to 256 query characters and 8 MiB of extracted text, runs in the background, and supports cancellation between pages. It does not OCR scanned pages, and text reading order can vary by PDF. `Merge another PDF…` opens a native dialog for a second input, then saves a new page-only merged copy. It is experimental and may omit annotations, bookmarks, forms, document metadata, or unusual page-tree structures. Merge requires the second input path to be representable as UTF-8 by the current `Request.parameter` contract; a non-UTF-8 path is rejected explicitly. Native save dialogs can be cancelled, outputs must have a lowercase `.pdf` extension, and the handler never overwrites existing paths; the source PDFs remain unchanged. All structural page operations are experimental and are not sanitization or redaction. The Hayro preview is an experimental raster route; unsupported PDF features may be missing or differ. Zoom enlarges the bounded raster and does not render again at higher resolution. The CLI route is `document-studio --cli pdf-preview input.pdf preview.png 1`. To open the viewer directly, use `document-studio --preview-pdf input.pdf 1`.
- `pdf-text`: PDF text-layer extraction.
- `pdf-compare`: Compare two local PDFs and write a new JSON report. From the native PDF workspace, choose **Compare with PDF…**; the app prompts for the second PDF and a new `.json` report path. The headless operation accepts the second input path as its parameter. The report checks page count, available Info metadata, page-by-page extracted text, page dimensions and 224-pixel-edge raster previews. Inputs are limited to 32 MiB and 100 pages; extracted text is capped at 8 MiB per PDF. This is a screening tool, not a full object, accessibility, signature, archival fidelity or legal comparison. Hayro's known rendering omissions apply, and PDF parsing/rendering remains in-process rather than a security sandbox.
- `pdf-page-compare`: Render two selected local PDF pages with the bundled Hayro renderer and save a side-by-side PNG plus a JSON summary in the native preview. Parameter example: `{"second_pdf":"/path/to/other.pdf","first_page":2,"second_page":5}`. Each document uses the existing 32 MiB, 1,000-page, 100,000-object and bounded-render limits; each page is rendered at no more than 1,400 pixels per edge and 1.5 million pixels, and the composite is limited to 4.5 million pixels. Exact changed-pixel and mean RGB differences are reported only when both raster dimensions match. This route compares rendered pixels only; it does not compare text, metadata, annotations, signatures or complete PDF structure. Identical means identical output from this Hayro renderer, not universal visual equivalence.
- `pdf-split`: In the native viewer, enter an inclusive page range such as `2-4` and choose a new PDF. This extracts that range into one page-only output; it does not create multiple split files. Existing paths and the source are preserved. Structural output may omit annotations, bookmarks, forms, document metadata, or unusual page-tree structures.
- `pdf-reorder` writes a new PDF using the requested page order. Enter every page once, for example `--cli pdf-reorder input.pdf reordered.pdf 3,1,2`. In the PDF workspace, use the earlier/later controls and save the resulting order as a new copy. The output omits annotations, bookmarks, forms and document metadata.
- `pdf-delete-pages` writes a new PDF without selected pages. Enter unique 1-based page numbers separated by commas. The result must retain at least one page. This page-tree rewrite can omit annotations, bookmarks, forms and document metadata; it is not redaction or sanitization.
- `pdf-merge`: The native viewer can merge the open PDF with a second PDF into a new page-only output. Existing paths and both sources are preserved. The Request interface requires the second path to be UTF-8; unsupported paths are rejected rather than converted lossily.

Limitations: Basic DOCX only; inline Markdown and layout omitted. EPUB offers a bounded plain-text reader, not a layout-preserving reader or complete EPUB validator. Citation interchange is a bounded supported-field subset, not a citation manager or style engine. `pdf-compare` reports selected metadata, extracted text, page geometry and low-resolution previews; `pdf-page-compare` separately emits a selected-page side-by-side raster and pixel metrics. Both inherit Hayro fidelity limits, and neither compares complete PDF structure. PDF parsing and decompression limits remain incomplete, active content can survive split/merge, and these operations are not redaction or sanitization. Page-only merge drops page annotations, document-level metadata/bookmarks/forms, and may lose inherited or unusual structures; no independent reader validation yet. No Office fidelity or legacy conversion engines.

No output overwrite is allowed. No accounts, ads, telemetry or runtime downloads are intended. Do not use this unverified snapshot with valuable or hostile input. Citation and donations are voluntary.

- `pdf-rotate`: Enter a page range and a clockwise angle, such as `2-4,90`, and choose a new PDF path. Angles of 90, 180 and 270 degrees are supported. Rotation is relative to each selected page’s current orientation.
